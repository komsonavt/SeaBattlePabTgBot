# Морской бой для Telegram (Kotlin / JVM 21)

Три режима: компьютер, коллега по приглашению, турнир. Состояние хранится в PostgreSQL.

## Игровое поле

Интерфейс перенесён из `TELEGRAM_BATTLESHIP_CUSTOM_EMOJI_HANDOFF.md`:

- Своя карточка: Rich Message с таблицей 10×10.
- Карточка соперника: 10 рядов по 5 кнопок и переключение А–Д / Е–К.
- Раскрытые клетки и поле во время чужого хода отключены.
- Каждая кнопка содержит ID партии и ревизию персональной карточки. Сервер также проверяет игрока, личный чат и ID сообщения.
- Переключение половины не меняет очередь хода или дедлайн.

Используется [Telegram Rich Messages](https://core.telegram.org/bots/api#sendrichmessage). Для этих методов добавлен HTTP-адаптер на Kotlin: текущая версия Telegram SDK используется для long polling и обычных сообщений. Python и webhook не нужны.

## Оформление

Без конфигурации отображаются обычные эмоджи. Для рисунков коллеги скопируйте `brand-emoji.example.json` в свой файл, замените `id` на реальные `custom_emoji_id`, а `alt` — на соответствующий `emoji` из Telegram. Задайте `BRAND_EMOJI_FILE` — путь к файлу. В переданном документе реальных ID нет.

В своей карточке не более 100 вхождений custom emoji, в карточке соперника не более 50. Корабли соперника не включаются в разметку. Окружающая потопленный корабль вода пока отображается как промах, как в исходной модели.

Для Docker задайте в `.env` переменную `BRAND_EMOJI_HOST_FILE=./brand-emoji.json` с путём к своему файлу. Compose подключит его как `/app/brand-emoji.json`. По умолчанию подключается пример с обычными эмоджи. Файл не должен содержать токен.

## Запуск и проверка

1. Скопируйте [bot.properties.example](/C:/Users/komsonavt/IdeaProjects/SeaBattlePabTgBot/bot.properties.example) в `bot.properties` и заполните токен, username, ID форума модерации, ID трёх тем и ID администраторов. `bot.properties` исключён из Git. Переменные окружения имеют приоритет.
2. Для Docker скопируйте `.env.example` в `.env` и задайте надёжный `POSTGRES_PASSWORD`.
3. Соберите JAR локально: `gradlew.bat jar` (Windows) или `./gradlew jar`.
4. `docker compose up --build -d`. Сервер использует готовый JAR и не компилирует Kotlin.

При запуске схема дополняется колонкой `games.ui_state` без удаления существующих партий. Старые карточки заменяются новой парой; старые кнопки не делают ход. `/mygames` повторно синхронизирует карточки и восстанавливает удалённые сообщения.

## Доступ и форум модерации

Проверка корпоративного канала не используется. Пользователь без доступа получает Rich-сообщение с кнопкой «В бой!», указывает имя и актив, после чего заявка появляется в теме `MODERATION_TOPIC_ID` с кнопками одобрения и отклонения. При одобрении приглашение в игру, если оно было, продолжается автоматически.

В `EXPORTS_TOPIC_ID` бот отправляет CSV заявок на турнир. Сообщение администратора в теме `BROADCASTS_TOPIC_ID` рассылается всем одобренным пользователям. Для получения сообщений из тем бот должен быть добавлен в форум; при включённом Privacy Mode добавьте его в администраторы.

## MVP NMH Team

Проверка доступа использует полный Bot API ID из `ACCESS_CHANNEL_ID` или `CORPORATE_CHAT_ID` — например, `-1001234567890`. Не добавляйте `-100` к уже полному ID. Для проверки подписки бот должен быть администратором канала; ссылка для кнопки задаётся в `CORPORATE_CHAT_URL`.

В PvP на ход отводится 3 минуты. Первые три истечения передают ход сопернику; четвёртое для этого игрока завершает партию техническим поражением. В игре с компьютером дедлайна нет. Карточка соперника показывает время, счёт уничтоженных кораблей, пропуски и последнее событие.

`/leaderboard` показывает топ-15 по играм с коллегами. `/tournament` открывает предварительную запись и не запускает сетку автоматически. Администратор получает CSV выгрузку заявок из интерфейса турнира.

Ход вместе с ответом компьютера сохраняется до обновления Telegram. Завершение партии и результат турнирного матча фиксируются одной транзакцией. При ошибке БД состояние в памяти восстанавливается. Дедлайны проверяются каждые 5 секунд, включая после перезапуска. Неудачные обновления карточек повторяются примерно раз в 30 секунд; необходимость синхронизации сохраняется в БД.

Новая игра не отменяет текущую: сначала завершите её или используйте `/surrender`. Приглашение нельзя принять самому или во время активной игры одного из участников.

Приложение рассчитано на один процесс бота: обновления и таймауты сериализованы общим монитором. Для нескольких экземпляров потребуется координация действий через БД.

Перед использованием брендированного оформления проверьте реальные ID и вид карточек в Telegram Desktop и на телефоне. Автотесты проверяют разметку, протокол действий и обработку ответов API, но не отрисовку клиентом Telegram.
